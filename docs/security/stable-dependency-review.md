# Stable dependencies and maintained MCP runtime

Reviewed 2026-10-21 from fetched main. All five open dependency PRs (183–187) are covered by the consolidated update: current stable Rust 1.99.1 in builds/CI/releases, all direct/dev crate requirements and compatible locked transitive packages, immutable Action pins and used tooling. The consumer MSRV remains 1.97.1. Cargo geiger and supply-chain pins move to 0.14.0 and 0.3.8. Current audit/deny/hack/coverage/SBOM/cross/semver/deadlinks pins were checked against official stable releases. No Cargo feature is removed.

All 89 original published-image findings are reviewed individually in [the historical artifact report](historical-image-alert-review.md), using both original immutable platform filesystems and vendor evidence: 19 proven component/architecture false positives, 67 retained package detections and three component uncertainties. None of the retained findings is called safe merely because current source no longer tracks the old inline Dockerfile. The old image remains publicly available.

A maintained checked-in Dockerfile now builds the actual MCP server with all JWT/OAuth features and a static init process. It deliberately adapts the static-musl runtime pattern: explicitly select maintained system musl instead of Rust’s older bundled libc, retain static PIE, prove linker/archive provenance and reject dynamic dependencies. Copy fixed CA data and the exact installed supplier record together. The final image omits the old broad Debian userspace/OpenSSL/account-management packages. Builder compilation uses two jobs. This is an implementation fix; replacing public tags and addressing immutable-image retention requires the reviewed normal publication workflow after merge.

The environment configuration now enforces requested JWT/OAuth modes, fails closed when the requested feature or signing secret is absent, removes demo password fallbacks, and requires configured password credentials. Preserve both existing premium-tier spellings and stdio/default modes. Compatibility and focused regression evidence are documented in [the authentication review](authentication-runtime-review.md).

Local validation passed the full repository `make ci-local` gate: strict lint, all-feature/no-feature/MCP/JWT/OAuth tests, examples, doctests/documentation/contracts and all 20 feature combinations. Final focused configuration tests pass under the plain MCP, JWT and OAuth builds; strict Clippy, unchanged MSRV, audit with warnings denied, and deny also pass. Python syntax, Actionlint and diff checks pass. The complete ARM64 image passes static/native/CA verification, real health/JWT/OAuth/stdio fixtures, an actual MCP file-report HTTPS request plus issuer/hostname rejection, and a fresh Trivy 0.76.0 OS/Cargo scan with zero findings at every severity.

Native AMD64 and ARM64 CI each build and verify their complete image independently and scan all severities including unfixed advisories. Only a successful tested/scanned normal push can publish those exact platform images. PR builds do not publish. AMD64 retains the original non-matrix analysis identity while ARM64 uses a distinct category; no historical analysis is deleted. The historical report documents supported CodeQL identity migration and post-upload verification.
